<h2 id="what-is-variable-jump-height">Variable jump height: a tap hops, a hold jumps</h2>

Obstacles ask for different heights. A spiked ceiling wants a short hop, a wall wants the whole jump. Variable jump height lets the player pick any height between 1.1 and 3.6 tiles with the same button, and the button reads the hold the way players already expect. Without it, every obstacle in the game has to be designed around one arc.

<h2 id="how-to-implement">How to implement variable jump height</h2>

1. **Watch for the release while rising.** If the button comes up while the character still moves upward, mark the jump as cut.
2. **Raise gravity until the top.** A cut jump rises with gravity ×3, so the arc bends instead of breaking. Halving the upward speed on release also works, but the arc gets a visible kink at that instant.
3. **Cut once per jump.** Pressing again mid-air must not undo it.
4. **Protect wall jumps.** Block the cut for the first 220 ms of a [wall jump](/blog/wall-jump/), or someone mashing the button against a wall loses height on every kick.

```gdscript
	gravity = p.gravity_up
	if _jump_cut:
		gravity *= p.jump_cut_gravity_mult
```

`jump_cut_gravity_mult` is 3, and it is the only number to tune.

<h2 id="quick-answers">Quick answers</h2>

<h3 id="short-hop-height">How short should a short hop be?</h3>

About 30% of a full jump: 1.1 tiles against 3.6. Low enough to stay under a three-tile spiked ceiling, long enough (2.5 tiles at a run) to clear a two-tile gap.

<h3 id="cut-velocity-or-gravity">Should I cut the velocity or raise the gravity?</h3>

Raise the gravity if you want the arc to stay smooth; cut the velocity if you want the release to be visible. Both work.

<h3 id="hold-window">How long should the hold window be?</h3>

Here the hold counts all the way to the top, 0.38 s. [Celeste](https://github.com/NoelFB/Celeste/blob/master/Source/Player/Player.cs) caps it at 0.2 s: while you hold, the upward speed doesn't drop.
