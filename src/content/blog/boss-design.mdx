A **boss fight** is an exam: it teaches nothing new and combines what the player already learned. This one has three attacks with their own warnings, collapses for **2.2 s** after seven hits, and speeds up at half health.

<h2 id="what-makes-a-good-boss">Boss attacks: questions the player already answered</h2>

Each attack repeats an earlier enemy's question and takes the same answer. After every attack the boss recovers for 0.8 s: your turn to hit it.

<h2 id="random-with-rules">Random boss attacks, with rules</h2>

A fixed order gets memorized instead of read. So the pick is weighted by distance and never the same attack three times in a row: within 260 px the hammer comes half the time, further away a quarter. You can't predict the next attack, but you can predict the mood.

<h2 id="stagger-bar">Stagger bar: aggression turned into an opening</h2>

The boss never flinches from a single hit, so the stagger bar is where your aggression shows: the seventh hit drops it for 2.2 s with its contact damage off. Sekiro builds its whole combat on the same idea, [posture](https://sekiroshadowsdietwice.wiki.fextralife.com/Posture).

<h2 id="boss-phases">Boss phases: the same attacks, faster</h2>

At half health the boss roars for 0.9 s, so you notice the rules just changed. Then warnings are multiplied by 0.85 and recoveries by 0.72, with no new attacks to learn mid-fight.

<h2 id="how-to-implement">How to implement a boss fight</h2>

1. Build the boss on the regular enemy loop, and add only an attack selector and a hit counter.
2. Weight each pick by distance, and drop the last attack from the pool once it has come twice in a row.
3. Ignore hits during the stagger so collapses can't chain, and if the bar fills mid-jump or mid-charge, collapse when the attack ends, not in mid-air.
4. Put the checkpoint at the door, and close the gates only once the player is inside and clear of both.

func _choose_attack() -> void:
	var far := absf(to_target().x) > 260.0
	var weights := {
		&"embestida": 3.0 if far else 2.0,
		&"martillo": 2.0 if far else 3.0,
		&"rafaga": 3.0 if far else 1.0,
	}
	if _repeats >= 1:
		weights.erase(_last_attack)   # como mucho dos veces seguidas


func _on_damaged(hit: Hit) -> void:
	super(hit)
	if state == &"staggered":
		return   # ya está desplomado: los golpes no alargan la apertura
	# AGUANTE: cada golpe suma; al llenarse, se desploma.
	poise_damage += 1
	if poise_damage >= poise:
		if state in [&"idle", &"recover", &"windup", &"burst", &"roar"]:
			_stagger()
		else:
			_stagger_pending = true   # en pleno salto o embestida: al terminar

<h2 id="quick-answers">Quick answers</h2>

<h3 id="how-many-attacks">How many attacks should a boss have?</h3>

Few enough to learn in a handful of attempts. This one has three, and its script says why: better three that read well than ten that confuse.

<h3 id="random-but-fair">How do you make boss attack patterns random but fair?</h3>

Put rules on the randomness: weight the choice by distance, never repeat an attack three times in a row, and keep every warning. The order can't be memorized, but the next move can always be read.
